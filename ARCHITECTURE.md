# Space Habitats RAG - Architecture Documentation

**Version:** 5.0.0  
**Last Updated:** January 2026

## Overview

Space Habitats RAG is a SaaS platform that provides an AI-powered knowledge base for space habitat research and design. The platform enables researchers, engineers, and enthusiasts to query a curated collection of NASA and arXiv documents using natural language, with responses generated by large language models (LLMs).

## Database Schemas

### PostgreSQL Tables

#### Core Tables

```sql
-- Users and authentication
users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(255) UNIQUE NOT NULL,
  password_hash VARCHAR(255) NOT NULL,
  email VARCHAR(255),
  role user_role DEFAULT 'user',           -- ENUM: 'user', 'admin'
  llm_preference llm_preference DEFAULT 'grok',  -- ENUM: 'grok', 'claude', 'both'
  subscription_tier VARCHAR(50) DEFAULT 'free',
  subscription_status VARCHAR(50) DEFAULT 'active',
  stripe_customer_id VARCHAR(255),
  is_beta_user BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
)

-- Session storage
sessions (
  sid VARCHAR PRIMARY KEY,
  sess JSON NOT NULL,
  expire TIMESTAMP NOT NULL
)

-- Document chunks with embeddings
document_chunks (
  id SERIAL PRIMARY KEY,
  chunk_index INTEGER,
  content TEXT,
  embedding vector(1024),      -- pgvector
  metadata JSONB,              -- title, source, tags, category
  source_type VARCHAR(50),
  source_id VARCHAR(255),
  processed_at TIMESTAMP DEFAULT NOW()
)

-- Query logging
query_log (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id),
  query_text TEXT,
  response_time_ms INTEGER,
  chunks_used INTEGER,
  created_at TIMESTAMP DEFAULT NOW()
)

-- User feedback
feedback (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  query_id INTEGER,
  feedback_type VARCHAR(20),   -- reaction, rating, relevance, general
  reaction VARCHAR(20),        -- thumbs_up, thumbs_down
  rating INTEGER CHECK (1-5),
  document_relevance VARCHAR(20),
  comment TEXT,
  created_at TIMESTAMP DEFAULT NOW()
)
```

#### Subscription Tables

```sql
-- Subscription tiers
subscription_tiers (
  id SERIAL PRIMARY KEY,
  tier_key VARCHAR(50) UNIQUE,  -- free, basic, professional, enterprise
  name VARCHAR(100),
  description TEXT,
  features JSONB,
  is_active BOOLEAN DEFAULT TRUE
)

-- Tier pricing
tier_pricing (
  id SERIAL PRIMARY KEY,
  tier_id INTEGER REFERENCES subscription_tiers(id),
  price DECIMAL(10,2),
  currency VARCHAR(3) DEFAULT 'USD',
  billing_period VARCHAR(20) DEFAULT 'monthly',
  stripe_price_id VARCHAR(255)
)

-- User subscriptions
subscriptions (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id),
  tier_id INTEGER REFERENCES subscription_tiers(id),
  stripe_subscription_id VARCHAR(255),
  status VARCHAR(50),
  current_period_start TIMESTAMP,
  current_period_end TIMESTAMP,
  cancel_at_period_end BOOLEAN DEFAULT FALSE
)
```

#### Project Tables (Enterprise)

```sql
-- Projects
projects (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  name VARCHAR(255) NOT NULL,
  description TEXT,
  objectives TEXT,              -- Injected into LLM system prompt
  constraints TEXT,             -- Injected into LLM system prompt
  is_active BOOLEAN DEFAULT TRUE,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
)

-- Project filters
project_filters (
  id SERIAL PRIMARY KEY,
  project_id INTEGER REFERENCES projects(id) ON DELETE CASCADE,
  filter_type VARCHAR(50),      -- source, keyword, date_from, date_to, nasa_center
  filter_value VARCHAR(255),
  created_at TIMESTAMP DEFAULT NOW()
)

-- Uploaded project documents
project_documents (
  id SERIAL PRIMARY KEY,
  project_id INTEGER REFERENCES projects(id) ON DELETE CASCADE,
  gridfs_id VARCHAR(255) NOT NULL,
  file_name VARCHAR(255),
  original_name VARCHAR(255),
  file_size INTEGER,
  mime_type VARCHAR(100),
  content_text TEXT,
  embedding vector(1024),
  processing_status VARCHAR(20) DEFAULT 'pending',
  error_message TEXT,
  uploaded_at TIMESTAMP DEFAULT NOW()
)

-- Pinned knowledge base documents
project_pinned_documents (
  id SERIAL PRIMARY KEY,
  project_id INTEGER REFERENCES projects(id) ON DELETE CASCADE,
  document_mongo_id VARCHAR(255) NOT NULL,
  document_title VARCHAR(500),
  document_source VARCHAR(100),
  pinned_at TIMESTAMP DEFAULT NOW(),
  UNIQUE(project_id, document_mongo_id)
)

-- Bookmarked responses
project_bookmarks (
  id SERIAL PRIMARY KEY,
  project_id INTEGER REFERENCES projects(id) ON DELETE CASCADE,
  query_text TEXT NOT NULL,
  response_text TEXT NOT NULL,
  model_used VARCHAR(50),
  cited_documents JSONB,
  user_notes TEXT,
  tags VARCHAR(255)[],
  bookmarked_at TIMESTAMP DEFAULT NOW()
)
```

## Data Flow

### RAG Query Flow

```
1. User submits question
          │
          ▼
2. Generate embedding for question
   (HuggingFace multilingual-e5-large)
          │
          ▼
3. Vector similarity search in PostgreSQL
   (pgvector cosine similarity)
          │
          ▼
4. Retrieve top-k document chunks
   (default k=5)
          │
          ▼
5. Build context with chunks
          │
          ▼
6. Send to LLM(s) with system prompt
   (Claude, Grok, or Both)
          │
          ▼
7. Return formatted response with citations
          │
          ▼
8. Log query for analytics
```

### Project Query Flow

```
1. User submits question within project
          │
          ▼
2. Load project definition
   (objectives, constraints)
          │
          ▼
3. Generate embedding for question
          │
          ▼
4. Vector search in knowledge base
          │
          ▼
5. Include project documents in context
   (uploaded + pinned)
          │
          ▼
6. Build enhanced system prompt
   - Base prompt
   - Project objectives
   - Project constraints
          │
          ▼
7. Send to LLM(s)
          │
          ▼
8. Return response with project context
```

### Document Upload Flow

```
1. User uploads file (PDF/DOCX/TXT/MD)
          │
          ▼
2. Validate file type and size (<200MB)
          │
          ▼
3. Store in MongoDB GridFS
          │
          ▼
4. Create project_documents record (status: pending)
          │
          ▼
5. Return success to user immediately
          │
          ▼
6. Background processing:
   a. Update status to 'processing'
   b. Extract text (pdf-parse/mammoth)
   c. Generate embedding
   d. Store text and embedding
   e. Update status to 'completed'
          │
          ▼
7. Document available for project queries
```

## Security

### Authentication
- Session-based authentication with express-session
- Password hashing with bcrypt (12 rounds)
- Secure cookies with httpOnly, sameSite, secure flags
- CORS configured for specific origins

### Authorization
- Role-based access control (user, admin)
- Subscription tier-based feature gating
- Enterprise middleware for project features
- Project ownership verification

### Data Protection
- Parameterized SQL queries (SQL injection prevention)
- Input validation on all endpoints
- File type and size validation
- Rate limiting on sensitive endpoints
